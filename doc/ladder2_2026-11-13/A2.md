## Notes

Repos read: all 23 (vendor/ in go-grpc-graphql-microservices and the .env files in GO-Proof-Of-Stake-Blockchain, GO-proof-of-work-blockchain and go-postgres-gorm were never opened). Repos not finished: none. For GO-CQRS-Microservices and GO-Kafka-MongoDB-Prometheus-Grafana the feature/handler/DTO/mock/generated files were skimmed by name only; every pkg-level file named in the table was read in full.

Patterns seen in more than one repo:
- Retry on a startup dependency (DB, broker, container): GO-CQRS-Microservices (cenkalti/backoff, 3 places), go-grpc-graphql-microservices (tinrab/retry ForeverSleep, 4 mains). Both uncancellable; one unbounded. Suggest `retry` gain a total-elapsed cap option and the ladder decide on "retry forever at startup" (recommend: no; bounded attempts + elapsed cap, then exit non-zero).
- Offset pagination with page/size/totalPages: GO-CQRS-Microservices, GO-Kafka-MongoDB-Prometheus-Grafana (same file lineage, same `SetPage` copy-paste bug), go-grpc-graphql-microservices (skip/take). All lack an upper bound on size; both pagination.go files use float ceil. `page` should call NUM-INTEG-013 CeilDiv and clamp size.
- Multi-server run with cancel-on-first-error then graceful stop without a deadline: GO-CQRS-Microservices (echo-server.go, grpc-server.go), GO-Kafka-MongoDB-Prometheus-Grafana (server.go). Both call Shutdown with a cancelled or background ctx. lifecycle TB-LIFE-004 covers it; a drain-deadline test is the thing to keep.
- gRPC keepalive ServerParameters as a config block: both microservice repos. grpcx should carry documented defaults.
- Error -> gRPC code -> HTTP status mapping and problem details: GO-Kafka-MongoDB-Prometheus-Grafana (string matching on err.Error()), GO-CQRS-Microservices (problem-details library). grpcx status mapping + httpx WriteProblem, table-driven, no string matching.
- Global mutable state without a lock in handler code: go-echo-CRUD, go-fiber-CRUD, go-gorilla-mux-CRUD, go-gin-CRUD, GO-Loadbalancer, go-openai-discord-bot (IgnoredChannelsCache), GO-Proof-Of-Stake-Blockchain (validators), GO-P2P-Blockchain. Every one is a `-race` test case for guard.Guarded / store in-memory.
- `time.Sleep` as a scheduler or poll: GO-CQRS consumer.go, watermill demo, GO-grpc-demo, GO-P2P, PoS, PoW. All are schedule/synctest cases.
- Trace/correlation propagation through message headers: GO-CQRS (AMQP headers carrier) and GO-Kafka-MongoDB (opentracing spans). Suggests the pubsub message type should carry `Headers map[string]string` so adapters can propagate ids without a tracing dependency in core.

calcbench requests from this reading: (1) sorted-postings intersection (merge of two ascending int slices; ALG-HASH-006 is the unsorted form) if a search specialist package is ever built; nothing else missing for the toolbench-side patterns above.

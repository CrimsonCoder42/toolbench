## Notes
- Go release-note facts above are from the go1.18-go1.25 release notes as I know them; I did NOT fetch go.dev in this run (time cap). The lead should confirm the go1.26/go1.27 notes for anything newer (e.g. errors.AsType) before citing.
- Outdated or wrong idioms seen (one line each):
  - go_77 rate_limit main.go: per-IP map shared across request goroutines with no lock (data race).
  - go_82 server/main.go and server_with_sync_map/main.go use `sync` without importing it (do not compile); map never evicts; `LoadOrStore` allocates a limiter per request.
  - go_77/go_82 client: `resp.Body` never closed; `time.Sleep` pacing.
  - go_80 tcp server: nil conn after Accept error; data used as a Fprintf format string; stale `err` checked after write; no shutdown path.
  - go_71: `tx.Commit()` error ignored, no Rollback; Must* everywhere.
  - go_74/go_76: `context.Background()`/`context.TODO()` inside handlers instead of `r.Context()`.
  - go_75: `InsecureSkipVerify: true` disables the WebSocket Origin check (CSWSH risk).
  - go_76: `filepath.Join` for S3 keys; no upload size limit.
  - go_72: global config var + `log.Fatal` inside a loader.
  - go_78: response status never checked, so error bodies decode into the result type.
  - go_79: `slog.SetDefault` global; middleware loses the status code.
- Standard patterns missing from this slice of code-heim: retry with backoff+jitter as a core pattern (only implied by resty), circuit breaker, bulkhead, graceful HTTP server shutdown, idempotency key, outbox.
- calcbench gaps: MISSING exponential backoff with jitter (full / equal / decorrelated, AWS Architecture Blog "Exponential Backoff and Jitter", 2015). calcbench ratelimit meters and LRUCache are not concurrent-safe by design, so toolbench wraps them under one mutex (rows go_77, go_82).
- Package-name decisions for Devin: `limit` (not `rate`), `txn`, `config`, `blob`, `netx` (transport outside the current layer table), `Must` (recommend not shipping), shared `Option[T]` (recommend per-package options).
